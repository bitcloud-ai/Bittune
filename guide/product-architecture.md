# BitTune 完整产品架构

> 本文同时说明当前 `Bittune-main 0.4.0` 代码和完整 BitTune 产品路线。“已实现”仅指当前仓库中可找到的代码和测试；云端、社区、排行榜、知识回传和 Router 按产品路线标注，不代表已在本仓库中交付。

## 1. 一句话介绍

BitTune 让用户已有的单机、多卡节点或既有GPU集群，从“有硬件”走到“能提供可验证的模型API”：本地智能体检测、部署、压测和调优，云端提供认证组合、版本、镜像、团队与经验服务，社区和排行榜让可比、可复核的调优结果形成共享知识。

## 2. 总体逻辑

```text
用户 / 团队 / 设备厂商
              │
      CLI / TUI / Web控制台
              │
┌───────── 客户侧 Bittune Local ─────────┐
│ Pi对话智能体 / 会话恢复 / 工具选择          │
│ 环境检测 / 模型发现 / vLLM与SGLang受管执行 │
│ Baseline / 调优实验 / Candidate复测 / 报告      │
│ Run Record / Artifact / 本地SQLite证据            │
└──────────────────────────────────────┘
              │
       仅出站安全连接
       授权的最小化投影 ↑
       签名目录/版本/知识 ↓
              │
┌─────────── BitTune Cloud ───────────┐
│ 身份、组织、设备、版本和政策                    │
│ 经认证的模型/量化/引擎/工具组合目录          │
│ 签名Manifest、制品索引与可选Harbor镜像分发      │
│ 经验聚类、社区、排行榜、知识审批与灰度回传       │
│ 可选Router上架和Token供给                          │
└──────────────────────────────────────┘
```

## 3. 客户侧：当前Pi智能体版本

当前仓库使用 Pi `0.84.1` 相关包实现对话与TUI，但不把大模型直接当作执行器。智能体理解用户目标并选择受信任的领域工具；真实操作由固定的工程工具执行并留下证据。

已在当前代码中实现的主要能力：

- Linux/GPU/Docker/NVIDIA Runtime环境发现；
- 本机模型Snapshot、运行时镜像和已有服务发现；
- vLLM和SGLang服务的受限启动、就绪、探测、日志和停止；
- EvalScope性能测试、实测运行点和容量基线；
- 调优上下文、候选、Trial、对比、恢复和资源租约；
- 本地SQLite WAL、Run Record、Artifact、脱敏和证据查询；
- 会话恢复、新实验隔离和只读MCP参考工具。

## 4. 云端：认证、管理和分发

云端的核心不是代替客户执行，而是提供“哪些组合经过什么验证、适用于什么环境、应从哪个签名来源安装”的可验证产品事实。

路线包括：

- 用户、组织、角色、设备和多节点组管理；
- Local Agent版本、兼容性和升级策略；
- 模型、固定Revision、量化版本、推理引擎及其版本；
- 能力工具组合、依赖、许可证、SBOM、签名和审批状态；
- 制品索引和可选Harbor/客户镜像仓库分发；
- 租户、数据范围、Consent、配额、成本和地域政策。

## 5. 社区：交流的是可复核经验

社区不只是论坛，它把讨论、用户身份和可选分享的调优证据关联起来。规划功能包括：

- 用户/团队/设备厂商主页，可选公开名称、设备和已验证成果；
- 按设备、模型、引擎、调优方向分类的主题与项目展示；
- 对报告摘要、配置和知识包的评论、引用、关注和复现反馈；
- 维护者、高质量复现者和设备优化贡献者的徽章与信誉；
- 明确的私有、租户内和公开范围，由用户决定是否显示身份。

## 6. 排行榜：先可比，再排名

不同GPU、模型、量化、引擎和负载的数字不能混排。排行榜先按下列条件形成可比组：

```text
GPU型号+数量+拓扑
+ 模型+固定Revision+量化
+ 引擎+版本
+ 数据集/测试标准+输入输出长度+并发
+ 驱动/运行环境指纹
= 同类可比组
```

再生成不同维度的排名：

- 吞吐量排名；
- 首Token时延与端到端时延排名；
- 显存利用和资源余量排名；
- 长时间稳定性排名；
- Baseline到Candidate的调优改善率排名；
- 报告完整度、复现成功率和社区贡献排名。

排行榜只接受满足最低证据门槛的数据；未签名、环境不可比、负载不一致或存在资源竞用的结果不进入正式排名。

## 7. 知识回传与持续学习

产品知识闭环不是“用户一次成功，立刻把参数推给所有人”，而是：

```text
本地Evidence
→ 用户明确授权的Experience Record
→ 可比经验组
→ Knowledge Candidate
→ 质量/隐私/安全/许可证审批
→ 签名Knowledge Pack
→ 分阶段下发、可撤销、可回滚
→ 客户侧真实验证
```

失败、无收益和成功经验分开建模；任何云端先验都不直接成为部署授权。

## 8. Router与商业闭环

当设备上的模型服务完成端点可用性、身份、路由、计量、模拟收益和下架验证后，用户可选把它接入 Router，作为上游算力/模型Token供给方。Router上架不是Local调优的默认结果，需要独立授权、生产质量验收和商业协议。

## 9. 不可改变的产品边界

- 默认Local-first；不连云也能使用当前本地能力。
- 原始Prompt、模型输出、密钥、原始Evidence和数据集默认不上传。
- 云端目录、社区经验、排行榜和MCP只能提供参考、候选和解释，不直接授权客户端副作用。
- 模型、引擎和配置仍需在目标设备真实验证。
- 社区和知识共享必须有明确的数据范围、Consent、撤回和删除流程。
- 云端不成为第二套客户侧Run Record或Artifact事实源。
